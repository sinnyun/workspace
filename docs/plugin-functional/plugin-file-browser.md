# `plugin-file-browser` · 文件浏览

**状态：现有。** C 区文件/目录浏览内容插件；通过 `pane-slot:*` 自动进入各栏，在 topbar 提供地址导航与视图下拉，并向设置容器贡献“文件浏览”设置页。

## 功能与显示

- 每个 pane 独立显示后退、前进、上级、刷新、路径输入/提交、项目数，以及列表/网格/表格切换。菜单当前值可见；单栏由顶栏统一显示导航，多栏时每栏保留独立导航。
- 目录项排在文件前；三种显示方式共用同一条虚拟化流、同一套选择与焦点语义。显示名称、文件类型图标、大小和修改时间；目录无大小时留空。表格模式另有表头：名称/大小/修改时间/类型/标签五列，前四列点表头排序（首击升序、再击降序、三击回到目录读取顺序），标签列只展示、不可排序；列可见性可配。
- 网格按可见性懒加载 Windows 系统缩略图；通过 `plugin-windows-thumbnails` 所属的 `shell.thumbnail.read` 能力获取，关闭缩略图偏好后停止新请求并隐藏已有图。失败时回退类型图标，不由本插件或应用生成缩略图。列表行、网格卡片与表格标签列都显示该项关联标签的 chips：最多两条加 `+N` 折叠（悬停给出其余标签名），点击 chip 打开标签视图。标签只读：经 SDK `listTags`（`db.tags.list`）读取并订 `tags:updated` 重查，本插件不写标签存储。
- 空目录显示明确空态；读取错误显示原因和重试；路径输入校验失败保留原路径；快速切目录不得闪回旧结果。

## 处理与状态

- 输入 `fs.home`、`fs.list(path)`、`shell.thumbnail.read(path,edge,policy)`、只读的 `db.tags.list`，并订 `sidebar:selection:changed`、`slot:registered`、`slot:disposed`、`tags:updated`。每次列表请求附本地请求序号，只有当前 path/session/pane 匹配时接纳结果。缩略图只接纳当前可见条目和文件版本匹配的响应。
- 导航栈区分 push、back、forward、parent、refresh；refresh 替换当前历史项；路径切换成功后更新 `cwd`。标签视图也是历史栈里的普通项（栈项是编码后的视图标识，标题/地址栏显示 `标签「X」`，没有"上级目录"），标签被删时视图显示"已不存在"并可重试、撤销删除后自愈。focus Ref 只表示当前交互文件/目录，不把完整条目对象发给全局状态。
- 每栏的 `fm.file-browser.v1` 用 `activeTabId|paneId` 隔离路径、模式、历史和**当前排序**；默认模式/缩略图开关/表格列可见性放 `fm.file-browser.prefs.v1`（`{defaultMode,thumbnails,tableColumns}`）。显式的单栏模式优先于默认模式；新栏跟随默认值。排序不进任何存储：它只是这一栏这一次挂载的交互状态，重载后回到目录读取顺序，切走再切回表格也一样重置。名称一列结构上无法隐藏。
- 未点表头时行序严格等于 `fs.list` 返回的顺序（默认顺序归数据提供方，浏览器不重排）；文件夹成组在前由一个隐藏排序主键保证，因此升序和降序都不会把目录混进文件里。
- 列表完成显示目录数/文件数/读取耗时。虚拟行窗口只渲染视口附近条目（表格行定高，表头固定在滚动区之上，横向网格模板与每行严格一致）；应用短期结果引用与不支持类型负缓存受容量约束，停用/关闭时取消请求并释放图像资源；Windows 系统缓存由 Shell 独立管理。

## 插件间交流

- 接到 `sidebar:selection:changed` 时只处理本插件认识的 `kind`（目录、文件、`tag`）；Ref 是导航目标，不是数据本身。侧栏选目录后各栏按既定同步策略导航；`kind:"tag"` 的 Ref 打开对应标签视图（跨目录透镜，不因目录导航失效）。标签数据一律经 SDK `listTags` 只读读取，不读其他插件的私有存储。
- 用户聚焦行时发 `focus:changed {kind,id,sourcePlugin}`；详情容器据此挂载属性/预览/历史插件。焦点目标失效或离开可见目录时发 null/新焦点。
- 列表行、网格卡片和目录空白区域右键时，按 `browser.list.item`、`browser.grid.item`、`browser.empty` 等稳定 surface ID 调用 `host.contextMenu.open`；提供目标/选中 Ref、当前会话/栏和指针或键盘锚点，不自行绘制菜单，也不持有其他插件的动作项。表格行与列表行同属 `browser.list.item` 表面，因此动作集合与列表模式逐项一致，不需要菜单提供方认识新模式。
- 新 outlet 出现时扫描 `providedSlots("pane-slot")` 并注入；dispose 时撤销对应 pane contribution。不能从其他插件 import 视图组件。

## 设置、动效与验收

模式切换保持当前路径与有效焦点，列表/网格/表格样式轻量过渡；导航按钮有 disabled 边界状态；地址栏 Enter 提交、Escape 恢复当前路径。设置项立即影响所有实例。表头按钮给出当前排序方向的箭头，双击/Enter/Space 与列表一致进入目录或聚焦，Shift+F10 与右键得到同一菜单。

验收至少覆盖双栏/四栏路径隔离、前进后退分支、刷新不增栈、空目录、无权限/失效路径、快速切换过期响应、十万级数据虚拟化、Windows 缩略图命中/未命中/不支持的图标回退、缩略图开关及插件禁用/恢复；确认没有应用解码、canvas 绘制或自制缩略图路径。表格视图另覆盖：未排序时行序等于读取顺序、双向排序目录恒成组在前、三击清空回到读取顺序、隐藏键不进入界面、列开关在重载后仍生效且表头/每行网格模板一致、每栏模式与排序互不影响、千级与万级下的常驻 DOM 与滚动稳定性。标签 chips 与标签视图另覆盖：三种模式 chips 可见且 `+N` 折叠悬停给出其余名单、点击 chip 打开标签视图且界面不出现 `tag://` 编码、库中脏行不变成界面脏数据（同 path 折叠、按 seq 排序）、标签被删的失效提示与撤销后自愈、每栏记忆恢复后重新拉成员、表格标签列不可排序（批次 11，`.scratch/pw/run-i.mjs` 70/70）。
