# `plugin-storage-analysis` · 空间分析

**状态：已交付（P7-23/24，2026-10-10 取证）。** 扫描用户选定的目录树并以矩形图（echarts treemap）展示体积占用，用于回答"哪里最占地方"。不承担通用浏览、删除或清理操作。

## 用户入口与显示

- 顶栏 `topbar-zone` 贡献一个「空间分析」按钮，点开是一个**固定 560×640 的浮层面板**，内容在面板内滚动；任何状态切换（扫描中、已取消、缓存命中、下钻）都不改变面板尺寸。
- 选择根目录走 `shell.pickDirectory`；扫描期间状态行实时显示已统计条目与字节，进度按批推进（不是同步大循环，页面持续出帧）。**没有百分比进度**，因为遍历总数事先未知——如实显示"已统计 N 项 / M"而不是伪造。
- 矩形图只画当前层体积最大的前 24 块，其余合并成「其他（N 项）」，并保留能就地展开的明细入口；合并永远不会变成黑箱。
- 点击矩形即下钻（面包屑多出一层），返回上一后面包屑与图形一起回退。点进一个没有返回明细的目录时如实说明，而不是画一张空图。
- 颜色取自 Mantine token，且块上永远同时有文本与体积数字（不单靠颜色区分）。

## 数据来源与上限

- 卷元信息走 `sys.disk.list`；递归统计走 `sys.scan.start` + `sys.scan.cancel`，结果与进度只经 `scan:progress` / `scan:done` 事件回传，不伪装成 `file:operation:progress`。
- 后端遍历策略是定案：指向目录的符号链接**从不跟随**（循环因此不可能发生，也不重复计数）；读不了的目录按原因归类跳过（`not-found` / `denied` / `invalid-argument` / `read-failed` / `budget-exceeded` / `too-deep` / `symlink-skipped` / `not-a-directory`）并**一个字节都不计入总量**，界面上每个跳过项都有对应中文原因，旁边写明"不计入总量"。
- 边界值：单次扫描 120 000 条目、递归深度 128、每扫描 8 个工作线程、同时最多 3 个扫描；超出条目/深度上限时聚合结果带 `truncatedAtDepth` 或跳过原因，面板写明"只展开到第 N 层"而不是静默截断。
- 聚合 DTO 每个节点的 `bytes` 对目录是**子树总量**，并附按小写扩展名切分的 `kinds`，所以"这一层里 `.psd` 占了多少"不需要第二次遍历。

## 缓存

内存缓存以**根目录路径**为 key（尾斜杠归一，`/demo/` 与 `/demo` 是同一次扫描），带 TTL。命中时面板明写"结果来自 <时刻> 的缓存"并给出扫描时刻，同时提供「重新扫描」按钮绕开缓存。`file:changed` 落在某条缓存的根目录下就作废那一条并说明原因，**兄弟路径的缓存不受牵连**。取消或失败的扫描不写缓存。

## 取消

取消在时间片边界有界停下；终态带 `cancelled: true`，界面只显示"已取消"与统计不完整说明，不画半截矩形图、不写缓存，并提示重新扫描才能得到完整占用。

## 与其他插件的关系

面板是自有可视化，不修改 `plugin-file-browser` 的当前目录或历史栈；本插件只订阅事件（`scan:progress` / `scan:done` / `file:changed`），不向外发事件。删除一个文件后重新扫描能反映新统计——因为 `file:changed` 已经作废了缓存。
